## Problem Statement

#547: add `pdb quotas [--json] [--refresh | --offline]` and a shared quota service, following the merged contract doc/design/github-quotas.md (#546). The serve page (#548) is out of scope but must reuse the same service.

## Our Approach

One pure view builder (`buildQuotaView`) over one normalized `GET /rate_limit` reading, wrapped in an in-memory `QuotaService` that holds per verified host/login state. The CLI is a thin parser and text renderer over the typed view; JSON is the view itself.

## Implementation

- `src/github/quotas.ts`: normalization (safe integers only, derived `used` labelled, contradictions flagged rather than clamped, 20-row cap with omitted counts), row states (unknown, zero-limit, inconsistent, reset-passed, exhausted, critical, warning, normal), typed notices, secondary-limit block that is always unmetered, header/aggregate discrepancy notices, and the service (60 s TTL, 10 s failure cooldown, 5 min last-good stale window, 5 s deadline, coalescing with per-reader abort, generation guard against late results, retry embargo, offline with zero requests, clock rollback as unknown age).
- `src/github/quotascli.ts`: argument parsing, context resolution through the existing `gh api user` resolver (one counted identity read; failure means unverified, never another login), text narration and exit codes.
- `src/cli.ts`: dispatch and help line. `scripts/package-test.ts`: installed help and a fake-gh `/rate_limit` run.

## Outcomes

The telemetry the view can show (events and header observations) is an injected snapshot. A new CLI process has none, so it says "no events observed in this process" rather than implying no throttling. #548 should pass an adapter over the serve cache's sanitized error ring.
