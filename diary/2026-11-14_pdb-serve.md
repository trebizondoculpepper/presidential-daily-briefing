## Problem Statement

Issue #373 asks for `pdb serve`, the foreground local HTTP server specified by the merged contract `doc/design/serve.md` (#372, PR #430): a read-only JSON API and HTTP MCP over one memory-only cache of collected GitHub facts, so agents on one machine stop collecting the same facts separately.

## Our Approach

Follow the contract's four-PR delivery plan as stacked PRs, each reviewable on its own, with every boundary (gh, clock, signals, output, listen port) injected so tests run on ephemeral ports without GitHub. Reuse rather than rebuild: the existing read service, the MCP server factory, `sharedCollect`'s reference-counted coalescing (generalised into the cache), the SDK host/origin validators and Streamable HTTP transport.

## Outcomes

- A live run against this repository collected the implementer briefing in 6.2 s and served the repeat from the cache in 0.3 s with `source: "cached"` and the same `observedAt`; SIGINT exited 0 (recorded in #439).
- Two traps worth remembering. First, bundling: `dist/cli.mjs` inlines every imported module, so importing `src/mcp.ts` (which checks `argv[1]` against `import.meta.url` to decide whether it is the entry point) would have started the stdio server inside the CLI; the factory therefore moved to `src/mcp/server.ts`. Second, a collection queued under one gh login can finish after `gh auth switch`; its facts must be stored under the key of the login that collected them, which a test caught.
- `createMcpHandler` in SDK 2.4.0 is stateless per request, so sessions use the lower-level transport, as the contract allowed.
- Windows cannot deliver a catchable SIGTERM from another process; graceful shutdown there is console Ctrl-C/Ctrl-Break, covered in unit tests through injected signals and documented in `--help`.
