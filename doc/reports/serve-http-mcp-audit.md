## Notes

- Building the stdio side of the parity test showed that a stdio server without explicit configuration boundaries reads its own working directory's checkout. That is documented `pdb-mcp` behaviour (doc/design/mcp.md), and `pdb serve` with only `--repo` uses defaults. The parity test therefore gives both sides the same project-free configuration rather than treating the difference as a defect.
- The new `context` argument (#355, PR #485) is part of the shared input schema, so it reaches HTTP MCP without extra code. Its parity case can be added to this test once #485 merges.
- No product code changed. Everything this audit added is test coverage.
